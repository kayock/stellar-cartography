Archive Viewer

        
      

      

        When enabled, your browser talks directly to ESASky (sky.esa.int) — this app's
        local server is not involved and never sees that traffic. This app itself deliberately sends only
        the target name (when needed), RA, Dec, and field of view — no FOXAI workspace data, local file
        paths, Observation Deck records, or machine identity are ever included. Note that, like any
        website your browser visits, ordinary browser/network metadata (e.g. your IP address, user agent)
        may still accompany requests to ESASky regardless of what this app sends.
      


      

        
        
      


      

        
      

    


    

      
ESASky survey-layer controls

      

        These buttons switch ESASky all-sky HiPS survey layers via the documented
        postMessage API. Acknowledgement means ESASky accepted the layer name —
        not that useful tiles are present at the current coordinates. MAST
        scientific archive discovery is a separate panel below.
      

      

      

      

        
      

      

      

      

        
MAST scientific archive discovery

        

      


      

        What's the difference between these views?
        
    
        
    
          Archive visualization layer vs. individual telescope photograph:
          most buttons above load a stitched, all-sky mosaic (a "HiPS" layer) assembled from many
          observations over time — useful for browsing, but not a single photo. ESASky confirming that a
          layer exists does not by itself prove the selected coordinates have image coverage in it; a
          blank area in the viewer means that layer has no imagery there. A handful of famous targets also
          have individually-released Hubble/JWST outreach photographs; Hubble and JWST buttons also show
          MAST archive-availability lights (metadata only) when Online Archive Mode is on.
